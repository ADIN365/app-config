Hanapin ang Kotse Ko — Patakaran sa Privacy

Pinahahalagahan ng LazyWorks (ang ‘Developer’) ang privacy ng mga gumagamit ng Hanapin ang Kotse Ko (ang ‘App’). Inilalahad ang patakarang ito alinsunod sa Personal Information Protection Act ng Republika ng Korea.

1. Impormasyong pinoproseso

Pangunahing nakaimbak sa iyong device ang mga tala ng pagparada at larawan. Walang hiwalay na server ang Developer para mag-upload ng mga tala ng pagparada. Gayunman, maaaring maipadala ang data sa labas ng device sa pamamagitan ng mga panlabas na serbisyo at backup ng operating system na inilalarawan sa ibaba.

Impormasyon ng Bluetooth device (pangalan at MAC address)Awtomatikong pagtatala ng pagparada sa pamamagitan ng pagtukoy sa pagkonekta at pagkadiskonekta ng Bluetooth ng kotseLokal na database sa device

2. Layunin ng pagkolekta at paggamit

  • Awtomatikong pagtukoy at pag-save ng lokasyon ng paradahan
  • Pagpapakita ng lokasyon ng paradahan sa mapa para makatulong sa paghahanap ng kotse
  • Pagtatala ng palapag ng paradahan at mga larawan
  • Pagpapakita ng impormasyon ng paradahan sa mga widget sa home screen
  • Paghahatid ng ad, pagbili ng pag-alis ng ad at reward, pagsusuri ng paggamit at error, at pagbibigay ng abiso at update

3. Pagpapanatili, pagbura at backup

  • Nananatili ang kasalukuyang tala ng pagparada hanggang burahin mo ito o palitan ng bagong tala para sa parehong sasakyan. Nililinis ang mga larawan kapag pinalitan o binura ang kaugnay na tala; maaari ring burahin sa pagbukas ng App ang mga larawang hindi na ginagamit ng anumang tala.
  • Kapag naka-on ang kasaysayan ng pagparada, binubura ang mga entry na lampas sa piniling panahon (7, 30, 90 o 365 araw; default: 30) sa susunod na pag-save ng entry, hindi kaagad sa paglipas ng takdang panahon. Maaari mo ring burahin ang lahat sa screen ng kasaysayan.
  • Pinapayagan ng App ang Android backup at walang hiwalay na pagbubukod para sa database ng pagparada, mga setting o larawang nasa sariling storage ng app. Depende sa device, account, mga setting ng backup at limitasyon ng operating system, maaaring maisama ang mga ito sa cloud backup o paglilipat ng device at maibalik matapos muling i-install o magpalit ng device. Hindi direktang maa-access o mabubura ng Developer ang mga backup na ito ng operating system.
  • Ang pag-uninstall o pag-clear ng data sa mga setting ng device ay nagbubura ng data ng App sa device na iyon. Hindi nito sabay na binubura ang mga nagawang backup, data na natanggap na ng panlabas na serbisyo, o rekord ng pagbili sa Google Play. Pamahalaan nang hiwalay ang mga backup sa mga setting ng device o account.
  • Ang data ng panlabas na serbisyo ay saklaw ng patakaran sa pagpapanatili at naaangkop na mga setting ng bawat serbisyo. Pinapanatili ng Crashlytics ang mga bakas ng pag-crash at kaugnay na identifier sa loob ng 90 araw bago simulan ang pagbura. Nag-iiba ang tagal ng pagpapanatili ng analytics, ad, pagbili at access record ayon sa serbisyo at uri ng data, at hiwalay ito sa panahon ng kasaysayan ng pagparada.

4. Panlabas na serbisyo at paglilipat ng data

Pinoproseso ng mga serbisyong ito ang data kapag gumagana ang kaugnay na feature, kabilang ang mga identifier at diagnostic information na awtomatikong kinokolekta ng SDK. Kaya hindi namin sinasabing anonymous ang lahat ng data. Depende sa provider at mga setting, maaaring iproseso ang data sa labas ng iyong bansa, kabilang ang Estados Unidos. Ipinaliliwanag ng mga patakaran ng provider ang pagpapanatili, paglilipat at pagbura.

  • Google AdMob — Pinoproseso ang IP address (na maaaring gamitin upang tantiyahin ang pangkalahatang lokasyon), ad at app identifier, panonood, pag-click at iba pang pakikipag-ugnayan sa ad, at diagnostics para maghatid at sukatin ang mga ad at maiwasan ang pandaraya. Nakasalalay sa mga setting ng device at ad ang magagamit na identifier at pagproseso. (Patakaran sa Privacy ng Google)
  • Firebase Crashlytics — Nagpapadala sa Google ng installation identifier, impormasyon ng device, OS at app, crash stack, exception at diagnostic log para suriin ang mga error. Kapag nabigong kumuha ng lokasyon, maaaring kasama sa error log ang Bluetooth MAC address ng sasakyan. (Firebase)
  • Firebase Analytics — Pinoproseso ng Google ang app-instance at ad identifier, impormasyon ng device, tinatayang lokasyon at mga event ng paggamit. Ipinapadala rin ng App ang uri ng signal ng pagkaputol ng Bluetooth (HFP, A2DP, ACL) at oras bago lumabas ang popup. Hindi kasama sa mga custom event na ito ang coordinate ng pagparada, larawan, pangalan ng sasakyan o MAC address.
  • Google Play — Google Play ang humahawak sa mga pagbili. Tinitingnan ng App ang status at token ng pagbili at kinukumpirma ito upang ipatupad o ibalik ang pag-alis ng ad. Hindi direktang natatanggap ng Developer ang detalye ng paraan ng pagbabayad, gaya ng numero ng card. Hindi pinatitigil ng pag-alis ng ad ang lahat ng analytics, error reporting o backup.
  • GitHub — Kapag kumukuha ng abiso, tip at impormasyon ng bersyon mula sa GitHub o binubuksan ang patakarang ito, ipinapadala ang IP address at impormasyon ng request sa hosting provider. Ang pag-load ng larawan ng abiso o pagbukas ng link ay nagpapadala rin ng impormasyon ng access sa kaugnay na server. Hindi ikinakabit ang database ng pagparada o mga larawan sa request para sa configuration ng abiso. (GitHub)
  • Android / Google Play services — Gamit ang pahintulot sa lokasyon, kumukuha ang App ng coordinate sa pamamagitan ng Google Play services at naghahanap ng address gamit ang Android Geocoder. Maaaring maipadala ang coordinate at wika sa provider ng device na nagko-convert ng coordinate sa address. Nakasalalay ang pagproseso sa mga serbisyo sa lokasyon at setting ng device.
  • Maps — Kapag binuksan mo sa mapa ang lokasyon ng pagparada, ipinapasa ng App ang coordinate at pangalang ipapakita sa napiling map app, gaya ng Google Maps, NAVER Map, KakaoMap o TMAP. Ang susunod na pagproseso ay sumusunod sa patakaran ng serbisyong iyon.

6. Iyong mga pagpipilian at karapatan

  • Maaari mong burahin ang tala ng pagparada sa main screen, o i-off ang pagtatala at burahin ang buong kasaysayan sa screen ng kasaysayan. Hindi nabubura ang mga dating entry kapag ini-off lang ang pagtatala.
  • Maaari mong baguhin o bawiin ang pahintulot sa lokasyon, Bluetooth, camera at iba pa sa mga setting ng device; maaaring malimitahan ang kaugnay na feature. Maaari ring pamahalaan ang ad ID at backup sa mga setting ng device o account.
  • Walang hiwalay na switch sa App para i-off ang analytics o error reporting. Hindi pinatitigil ng pagbura ng ad ID o pagbili ng pag-alis ng ad ang lahat ng panlabas na pagproseso ng data. Para sa data ng panlabas na serbisyo, gamitin ang privacy controls ng provider o makipag-ugnayan sa amin sa ibaba.
  • Makipag-ugnayan sa email sa ibaba upang humiling ng access, pagwawasto, pagbura o paghihigpit sa pagproseso. Susuriin namin ang kahilingan ayon sa naaangkop na batas. Hindi maa-access nang malayuan ng Developer ang mga talang nasa device lamang; burahin ang mga ito sa App o mga setting ng device.
